# Лабораторная работа №3: автоматическое реферирование

Рабочая программа без нейросетей. На входе JSON-массив текстов, на выходе JSON-массив рефератов в том же порядке. Каждый результат содержит не больше 300 символов, включая пробелы и пунктуацию. Ограничение проверяется программно. Для пустого документа возвращается пустая строка.

Система выбирает информацию на основе содержания документа. Это не алгоритм взятия первых 300 символов: учитываются леммы, связи предложений, связь с начальным блоком, позиция, повторы и доступная длина. Начало новости — один из признаков, первое предложение не включается принудительно.

## Быстрый запуск в Windows

Нужен Python 3.10 или новее. Распакуйте архив в отдельную папку, чтобы не затереть прежние файлы проекта.

Выберите интерпретатор `.venv` в PyCharm. Выполните команды в терминале из корневой папки проекта (создание окружения можно пропустить, если оно уже есть):

```powershell
py -3 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe main.py
```

Или с выбранным интерпретатором: `python -m pip install -r requirements.txt`, затем `python main.py`.

Откройте `results/summaries.json`. После установки зависимостей программа работает локально без интернета. Словарь pymorphy3 устанавливается вместе с пакетом; загрузка моделей и ключи API не нужны. BAT-файлы исключены. Фактическая проверка выполнена в Linux; запуск в Windows делается теми же Python-скриптами.

Простой запуск без аргументов читает `examples/input.json` и пишет `results/summaries.json` рядом с программой, независимо от рабочей папки. Явные относительные пути в аргументах считаются от текущей папки терминала.

## Свои тексты

Создайте `input.json` в UTF-8:

```json
[
  "Полный текст первого документа...",
  "Полный текст второго документа..."
]
```

```powershell
python main.py --input input.json --output results/my_summaries.json --explain results/my_details.json --report results/my_report.txt
```

Результат — именно массив строк, без заголовков и оценок. В `my_report.txt` сохраняются исходные документы, рефераты, длины и выбранные предложения; `my_details.json` содержит подробные оценки. Оба отчёта необязательны.

Формат результата:

```json
[
  "Реферат первого документа.",
  "Реферат второго документа."
]
```

Для интеграции с проверяющей системой поддержаны stdin/stdout:

```bash
python main.py --input - --output - < input.json
```

При таком запуске stdout содержит только JSON. Служебные сообщения идут в stderr. Если вход не является массивом строк, программа завершится с кодом 2 и понятным сообщением. Старый выходной файл при ошибке чтения или валидации входа не используется как новый результат.

Перенаправление `<` показано для bash/cmd. В PowerShell: `Get-Content -Raw -Encoding UTF8 input.json | python main.py --input - --output -`.

Можно вызвать функции из Python:

```python
from summarizer import summarize, summarize_many

summary = summarize("Текст одного документа...")
summaries = summarize_many(["Первый документ...", "Второй документ..."])
```

## Как устроен алгоритм

1. **Подготовка.** Razdel разделяет текст на предложения и токены. Дополнительное правило защищает точку внутри коротких названий вроде «Ай-Петри. Крым». Сохраняется связь каждого фрагмента с исходным предложением.
2. **Морфология.** pymorphy3 приводит русские слова к леммам. Преобразование затрагивает только признаки; реферат сохраняет исходные формулировки. Стоп-слова исключаются из признаков, отрицания `не`, `ни`, `без` сохраняются.
3. **TF-IDF.** Предложения одного документа считаются отдельными единицами. `TF = число вхождений`, `IDF = ln((N+1)/(DF+1))+1`, затем L2-нормализация строк.
4. **Взвешенный LexRank.** Считается косинусное сходство предложений, убираются петли и слишком слабые связи. Итеративный PageRank с телепортацией определяет центральность. Для вершин без связей используется равномерный переход.
5. **Ранжирование.** Итог — взвешенная сумма нормированного LexRank, близости к начальным содержательным предложениям и позиционного признака. Позиция: `1/sqrt(номер предложения)`. Штрафуются риторические вопросы, короткие фразы и некоторые цитаты. Для русского документа исключаются преимущественно иностранные предложения; сами иностранные названия не удаляются.
6. **Кандидаты сокращения.** Кроме исходного предложения рассматриваются варианты с удалением небольшого набора вводных оборотов и уточняющих причастных вставок. Допускается самостоятельная часть до точки с запятой при дополнительных проверках. Новые факты и слова не генерируются. Вариант теряет часть исходной оценки пропорционально сокращению.
7. **Отбор.** Из полезности вычитается штраф за сходство с уже выбранным (принцип MMR), применяется мягкий штраф длины. Нельзя выбрать два варианта одного исходного предложения. Есть порог полезности и остановка, поэтому лимит не обязательно заполняется полностью. Для распознанного зависимого начала из середины документа («Он…», «Об этом…») требуется выбранное предыдущее предложение, в том числе на первом шаге отбора. Это эвристика, а не разрешение местоимений по смыслу.
8. **Сборка.** Выбранные фрагменты возвращаются в исходный порядок, пробелы между ними учитываются в бюджете. Если ни один кандидат не подходит, используется запасное сокращение наиболее высокооценённого предложения по границам слов с многоточием. Факт такого сокращения отмечается в диагностике.

Это наша адаптация нескольких классических идей к короткому реферату, а не точная копия одной статьи. LSA заменён на LexRank. При запуске используется один итоговый алгоритм.

## Настройки

`config.json` содержит полный набор текущих настроек. Чтобы использовать отредактированный файл:

```bash
python main.py --input input.json --output results/custom.json --config config.json
```

Без `--config` используются такие же значения из `config.py`. Допускается файл только с переопределяемыми полями. Неизвестные поля и неверные диапазоны отвергаются; `max_chars` разрешён от 1 до 300.

Основные настройки:

| Поле | Значение по умолчанию | Назначение |
| --- | ---: | --- |
| `graph_weight` | 0.25 | Вклад LexRank |
| `lead_weight` | 0.35 | Связь с начальным блоком |
| `position_weight` | 0.40 | Позиция в документе |
| `lead_sentences` | 3 | Размер начального содержательного блока |
| `redundancy_weight` | 0.30 | Штраф за повтор информации |
| `min_relative_score` | 0.25 | Минимальная доля от лучшей оценки кандидата |
| `min_gain` | 0.12 | Порог предельной полезности относительно лучшего кандидата |
| `length_penalty` | 0.20 | Насколько предпочтительны короткие кандидаты |
| `compression` | true | Рассматривать сокращённые варианты |

Веса — обоснованные стартовые значения, а не заявленный глобальный оптимум. Проверка на 100 дополнительных статьях проводилась без подбора по их эталонам.

## Оценка на реальных данных

В архив входят все прежние наборы: 20 исходных статей с сохранёнными результатами LSA, дополнительные 100 validation-статей Gazeta и внешние 200 test-статей Gazeta + 200 test-статей XL-Sum. Всего 520 документов. Происхождение и условия использования указаны в `data/README.md` и `EXTERNAL_EVALUATION.md`. Данные уже подготовлены, повторное скачивание не требуется.

```bash
python evaluate.py
python evaluate.py --input data/gazeta_check100.jsonl --output results/check100.json --report results/check100_review.txt
python evaluate.py --input data/external_gazeta200.jsonl --output results/external_gazeta200.json --report results/external_gazeta200_review.txt
python evaluate.py --input data/external_xlsum_ru200.jsonl --output results/external_xlsum_ru200.json --report results/external_xlsum_ru200_review.txt
```

`python evaluate.py` обрабатывает те самые прежние 20 текстов. Откройте `results/review.txt`: там исходные документы, человеческие эталоны, новые результаты и прежний LSA. Все отчёты финальной версии уже находятся в архиве. Для подачи тех же статей как обычного массива используйте `python main.py --input examples/previous20_input.json --output results/previous20_summaries.json --report results/previous20_report.txt`.

Наборы использовались ранее и после исправления контекста пересчитаны без подбора весов. Это регрессионная проверка, не новый независимый тест. Разницу старых и финальных результатов смотрите в `VALIDATION.md` и `results/previous_metrics.json`.

Для полного скачанного Gazeta-файла:

```bash
python evaluate.py --input data/gazeta_val.jsonl --limit 100 --seed 1629 --output results/validation.json --report results/validation_review.txt
```

Поддерживаются JSONL (один объект в строке) и JSON-массив объектов. В каждом объекте обязательны строковые `text` и `summary`, необязательны `title`, `url`, `dataset_index`. Поле `baseline_summary` нужно только для сравнения со старым результатом и НИКОГДА не участвует в реферировании.

`evaluate.py` сохраняет метрики в JSON и полный отчёт для чтения. `metrics.py` реализует ROUGE-1, ROUGE-2 и ROUGE-L: латиница/кириллица/цифры, нижний регистр, ё=е, без стемминга, лемматизации и удаления стоп-слов. N-граммы считаются с кратностями; ROUGE-L — LCS по всему реферату, не ROUGE-Lsum. Сначала P/R/F1 считаются по документам, затем усредняются. При пустом результате метрики равны 0.

Эталоны сохраняются целиком, даже если длиннее 300 символов. Это явно отражено в отчёте: здесь нет незаметного обрезания человеческих рефератов. У преподавателя могут отличаться токенизация и протокол ROUGE.

## Подбор параметров

```bash
python tune.py --input data/gazeta_val.jsonl --limit 100 --seed 1629
```

Проверяются восемь комбинаций трёх весов и штрафа повторов. Критерий фиксирован: среднее F1 трёх ROUGE. Результаты сохраняются в `results/tuning.json`, выбранный конфиг — в `results/best_config.json`. Программа сама не заменяет рабочие настройки.

```bash
python evaluate.py --input data/gazeta_test.jsonl --limit 100 --config results/best_config.json --output results/test.json --report results/test_review.txt
```

Для выбора настроек и финальной оценки нужны разные наборы. Запуск подбора на комплектных 20 статьях технически возможен, но не даёт независимой оценки. Официальный test отдельно доступен у автора Gazeta; программа не скачивает его сама.

## Ограничения

Система ориентирована на русскоязычные новости. На статьях другого жанра позиционный признак может мешать. Лемматизация не использует контекст для снятия неоднозначности. Сходство слов и близость к началу не гарантируют распознавание одного и того же события: фоновые факты ещё могут попадать в результат. Удаление вставок ограничено несколькими правилами; сокращённые фразы надо проверять на смысл. Запасное усечение может дать незавершённую фразу (для одного неразрывного слова длиннее лимита — только маркер сокращения). Полноценное разрешение местоимений не реализовано. Для текстов с тысячами предложений плотные матрицы TF-IDF и сходства потребуют больше памяти.

ROUGE не проверяет фактическую верность. Итоговые примеры следует просматривать вручную; большой балл не заменяет содержательную оценку.
