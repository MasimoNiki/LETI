# Лабораторная №2 — язык запросов к каталогу парфюмерии

Формальная грамматика и синтаксический анализатор на Python 3.10+.
Используется только стандартная библиотека: устанавливать пакеты не нужно.
Обучения моделей, готовых NLP-парсеров и подключения к базе данных нет.

## Быстрый запуск

Распакуйте архив, откройте папку `perfume_dsl` в PyCharm и выберите Python 3.10+.
Запустите `main.py` или выполните в терминале этой папки:

```bash
python main.py
```

Программа разберёт 44 примера из `queries.txt`: 20 корректных и 24 с ошибками.
Ошибки в запросах — часть задания; после них программа продолжает работу.
Затем откройте `results/report.html` в браузере: там находятся графические деревья.
HTML работает локально и без интернета. Готовый пример отчёта уже включён в архив.

Файлы результатов:

- `results/report.html` — наглядные деревья SVG, подсветка ошибок.
- `results/results.txt` — дерево с отступами и диагностика, без скобочной записи.
- `results/results.json` — те же результаты в машинном формате.

Другой файл запросов (UTF-8, один запрос на строке):

```bash
python main.py --input my_queries.txt --out-dir my_results
```

Один запрос:

```bash
python main.py --query "найди ароматы с нотой кедра"
```

Ввод с клавиатуры (удобен для названий с кавычками в Windows):

```bash
python main.py --interactive
```

Пустая строка завершает интерактивный режим. Отчёт сохраняется после выхода.
Каждый запуск перезаписывает три файла в выбранной папке результатов.
Без параметров вход и выход находятся рядом с `main.py`, даже если запускать его
из другой папки; явно указанные относительные пути считаются от текущей папки терминала.

## Какие запросы допустимы

Порядок частей фиксирован:

```text
команда [все] [семейство] ароматы [бренд] [ноты] [сезон] [цена]
```

Квадратные скобки здесь обозначают необязательные части, вводить их не нужно.
Каждое условие встречается не более одного раза.

| Часть | Допустимые значения / формы |
| --- | --- |
| Команда | `найди`, `покажи`, `выведи` |
| Семейство | `древесные`, `цветочные`, `цитрусовые`, `восточные`, `свежие` |
| Объект | только `ароматы` |
| Бренд | `бренда "Dior"`, `бренда "Jo Malone London"`; произвольное непустое название |
| Одна включаемая нота | `с нотой кедра` |
| Несколько включаемых нот | `с нотами кедра и бергамота` (минимум две) |
| Исключаемые ноты | `без ванили`, `без ванили и мускуса` (одна или больше) |
| Сезон | `для зимы`, `для весны`, `для лета`, `для осени` |
| Цена | `дешевле N рублей`, `дороже N рублей`, `от N до M рублей` |

Ноты: `бергамота`, `кедра`, `ванили`, `розы`, `жасмина`, `мускуса`, `ветивера`, `сандала`.

Пример со всеми условиями:

```text
найди древесные ароматы бренда "Dior" с нотами кедра и бергамота для осени дешевле 15000 рублей
```

Ограничения:

- Регистр ключевых слов не учитывается; исходный регистр сохраняется в дереве.
- Токены разделяются пробелами или табуляцией, несколько пробелов допустимы.
- Названия брендов — в обычных двойных кавычках `"`, без вложенных кавычек и экранирования.
- Цены — целые неотрицательные числа без разделителей: `10000`, а не `10 000`.
- Слово `рублей` фиксировано даже для 1 и 2: это упрощение DSL, не проверка русской морфологии.
- Пунктуация вне кавычек, синонимы `духи`, `парфюм`, союзы `или` не поддерживаются.
- Наличие и исключение нот нельзя объединять в одном запросе этой версии.
- Проверяется синтаксис, а не смысл: существование бренда, реальная цена и порядок
  границ диапазона не проверяются. Фраза `от 9000 до 100 рублей` синтаксически допустима.

Границы языка выбраны для этой реализации; фиксированный порядок и словарь не являются
дополнительными требованиями преподавателя.

## Как работает программа

1. `lexer.py` выделяет WORD, NUMBER и STRING, сохраняя позиции символов.
2. `parser.py` проверяет последовательность по `grammar.ebnf` методом рекурсивного спуска.
   Каждая функция отвечает за своё правило или небольшую группу правил.
3. При успешном разборе создаются узлы `Node`. Листья — исходные токены, включая
   предлоги, союзы и числа. Ничего из корректного запроса не выбрасывается.
4. После запроса обязательно проверяется конец входа. Лишнее слово вызывает ошибку.
5. `render.py` формирует текст и графические деревья; `main.py` читает файл и сохраняет результаты.

`grammar.ebnf` — описание языка. Анализатор написан вручную и не загружает EBNF
как исполняемый файл: при изменении правил нужно согласованно изменить `parser.py` и тесты.

В именах правил EBNF пробелы опущены (`УсловиеНот`); в дереве для удобства чтения
они добавлены (`Условие нот`). Это одна и та же конструкция.
Белые блоки в HTML — правила грамматики, голубые — конкретные токены.
По умолчанию схема вписывается по ширине. Кнопка «Увеличить дерево» показывает
её в исходном размере с горизонтальной прокруткой. Деревья можно раскрыть по отдельности
или кнопкой «Раскрыть деревья».

## Ошибки

Лексическая ошибка — нельзя выделить допустимый токен, например незакрытая кавычка
или знак минуса перед ценой. Синтаксическая — токены выделены, но нарушено правило.
Лексер обрабатывает всю строку до синтаксического анализа, поэтому при наличии
лексической ошибки сообщает сначала её, даже если раньше есть синтаксическая.

Сообщение содержит этап, номер токена и символа (с единицы), фактический токен,
ожидаемые варианты и пояснение. У конца запроса позиция на один символ дальше строки.
Позиции считаются в символах Unicode, а не в байтах UTF-8. Для каждого запроса выводится
первая обнаруженная ошибка. Пустые строки файла пропускаются, исходные номера строк сохраняются.

## Проверки

```bash
python -m unittest discover -s tests -v
```

Проверяются положительные и отрицательные примеры, точные позиции ошибок, конец ввода,
все 16 сочетаний необязательных фильтров, неверный порядок, сохранение листьев дерева,
HTML-экранирование и запуск CLI на файле с BOM/CRLF из другой папки.
