# Лемматизация русского текста

Программа приводит слова к начальной форме и определяет часть речи. Готовые морфологические анализаторы не используются. Данные взяты из UniMorph и UD Russian SynTagRus.

## Как устроено

1. Сначала ищутся возможные разборы словоформы в объединённом словаре (UniMorph + SynTagRus).
2. Если слова нет, OOV-модуль подбирает лемму и POS по суффиксным правилам. Правила автоматически извлекаются из пар «словоформа — лемма»: учитываются последние 3–5 букв и количество разных лемм, подтверждающих замену.
3. Для предложения контекстная модель выбирает сочетание разборов по частотам POS-переходов и словоупотреблений из SynTagRus. Используется алгоритм Витерби.
4. Результат записывается как `токен{лемма=POS}`, знаки `, . ? !` убираются. Регистр исходного токена сохраняется; при поиске не различаются `е/ё` и регистр.

POS-теги используются в формате Universal Dependencies: `NOUN`, `VERB`, `ADJ`, `ADV`, `PRON`, `DET`, `ADP`, `PART` и другие. Дополнительные библиотеки не нужны (Python 3.10+).

## Запуск

Для работы нужна папка `data/` со следующими файлами из предыдущей версии проекта:

- `rus.tsv` — UniMorph;
- `ru_syntagrus-ud-train-a.conllu`, `ru_syntagrus-ud-train-b.conllu`, `ru_syntagrus-ud-train-c.conllu` — SynTagRus;
- `train.tsv` — данные для извлечения OOV-правил.

**`data/` не входит в архив.** Её можно скопировать из исходного проекта. Если данных нет, из корня проекта выполнить:

```bash
python download_dictionary.py
python download_syntagrus.py
python prepare_oov_data.py
```

При проблемах с загрузкой GitHub можно скачать исходные файлы вручную. Виртуальное окружение не требуется, при желании создаётся обычным способом.

Ввод в терминале, по одному предложению:

```bash
python interactive.py
```

Для выхода написать `выход`, `exit` или нажать Ctrl+C.

Для обработки файла `input.txt`:

```bash
python main.py --input input.txt --output results/output.txt
```

Если нужны все кандидаты для разбора ошибок:

```bash
python main.py --input input.txt --output results/output.txt --details results/details.jsonl
```

Пример:

```text
Они стали работать.
Они{они=PRON} стали{стать=VERB} работать{работать=VERB}
```

## Проверка точности

Использовались 500 предложений из тестовой части SynTagRus и отдельно 40 вручную размеченных примеров, в том числе с омонимией и сленгом. Сравнение ведётся по токенам; для лемм не учитываются регистр и различие `е/ё`. POS сравнивается строго по тегам UD.

| Набор | Предложений | Токенов | Лемма | POS | Лемма + POS |
|---|---:|---:|---:|---:|---:|
| SynTagRus test | 500 | 6559 | 96.72% | 94.39% | 93.46% |
| Ручные примеры | 40 | 188 | 96.28% | 97.34% | 95.21% |

На корпусном наборе правильная пара получена для 6130 из 6559 токенов. По источнику разбора: `DICT` — 94.90%, `OOV` — 65.34%, `FALLBACK` — 40.54% (точность пары). Ручные примеры не считаются независимым тестом: некоторые использовались при разработке.

Более подробные таблицы POS, численные результаты и примеры ошибок лежат в:

- `results/benchmark/corpus/` — корпусный тест (`report.md`, `metrics.json`, `errors.tsv`);
- `results/benchmark/manual/` — ручные примеры (те же файлы).

Сами тестовые предложения и эталонные разборы сохранены в `tests/`. Поэтому результаты можно повторить, не скачивая тестовый корпус заново:

```bash
python run_benchmark.py
```

Команда заново запускает основной алгоритм и вычисляет метрики. Чтобы сформировать другой тест из исходной части SynTagRus, нужен файл `data/ru_syntagrus-ud-test.conllu`:

```bash
python run_benchmark.py --rebuild --sentences 500
```

Или `--download --sentences 500` для скачивания файла и пересоздания теста.

## Ограничения

Хуже обрабатываются некоторые имена собственные, AUX/VERB, союзы с разными функциями и неизвестные слова. Контекст сейчас учитывает в первую очередь POS-переходы, без полного согласования по роду, числу и падежу. Суффиксные правила не всегда различают похожие леммы, например `лабуб` и `лабуба`.
